## 🎯 下一阶段开发计划

### Phase 2 Stage 3: 智能告警系统（待开始）

**目标**: 将系统从"被动查询工具"转变为"主动安全哨兵"

#### 核心功能
1. **告警规则管理**
   - 规则CRUD（创建/编辑/删除/激活/停用）
   - 可视化规则构建器
   - 规则列表查看

2. **触发条件**
   - 检测到特定目标类别
   - 检测数量超过阈值
   - 置信度超过阈值
   - 特定数据集/模型
   - 时间范围条件

3. **执行动作**
   - 邮件通知（SMTP）
   - Webhook回调
   - 系统内消息
   - （可选）钉钉/飞书通知

#### 数据库设计
```sql
CREATE TABLE alert_rules (
    id SERIAL PRIMARY KEY,
    user_id INTEGER NOT NULL REFERENCES users(id),
    name VARCHAR(100) NOT NULL,
    description TEXT,
    is_active BOOLEAN DEFAULT TRUE,

    -- 触发条件（JSON格式）
    conditions JSONB NOT NULL,
    -- 示例: {
    --   "target_classes": ["fish", "shark"],
    --   "min_count": 5,
    --   "min_confidence": 0.8,
    --   "dataset_id": 1
    -- }

    -- 执行动作（JSON格式）
    actions JSONB NOT NULL,
    -- 示例: {
    --   "email": {
    --     "enabled": true,
    --     "recipients": ["user@example.com"]
    --   },
    --   "webhook": {
    --     "enabled": true,
    --     "url": "https://example.com/webhook"
    --   }
    -- }

    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE alert_logs (
    id SERIAL PRIMARY KEY,
    rule_id INTEGER NOT NULL REFERENCES alert_rules(id),
    detection_id INTEGER NOT NULL REFERENCES detection_history(id),
    triggered_at TIMESTAMP DEFAULT NOW(),
    conditions_met JSONB,
    actions_executed JSONB,
    status VARCHAR(20) DEFAULT 'success'  -- success/failed
);
```

#### 实施步骤
1. **后端开发** (4-5小时)
   - 创建数据库模型和迁移
   - 实现 CRUD 操作
   - 实现规则引擎（条件匹配逻辑）
   - 实现动作执行器（邮件/Webhook）
   - 在 Celery 任务中集成规则检查

2. **前端开发** (3-4小时)
   - 告警规则列表页
   - 规则创建/编辑页（可视化构建器）
   - 告警日志查看页

3. **测试和文档** (1小时)

#### API 端点设计
```
POST   /api/v1/alerts              # 创建告警规则
GET    /api/v1/alerts              # 获取告警规则列表
GET    /api/v1/alerts/{id}         # 获取规则详情
PUT    /api/v1/alerts/{id}         # 更新规则
DELETE /api/v1/alerts/{id}         # 删除规则
```

#### 技术要点
- 规则引擎：使用 Python `eval()` 或专门的规则解析库

- 条件匹配：在 Celery 任务完成后自动检查所有激活的规则
