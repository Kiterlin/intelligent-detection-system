# 项目结构说明（2025 Q4 版本）

> 智能目标检测系统现已进入第二阶段，整体目录组织、服务边界和数据流均已比初版复杂。本文件按照“顶层 → 后端 → 前端 → 运行数据”顺序介绍实际结构，并在每个模块下列出关键文件及职责，方便排查问题或扩展功能。

---

## 顶层目录概览

| 目录 / 文件 | 说明 |
|-------------|------|
| `backend/`  | FastAPI + Celery + YOLO 后端代码。 |
| `frontend/` | Vue 3 + Element Plus 前端项目。 |
| `docs/`     | 阶段计划、技术参考、需求文档（含本文件）。 |
| `Figures/`  | 开发阶段截图或错误提示（Vite overlay等）。 |
| `logs/`     | `backend.log`、`celery.log` 等运行日志（`start.sh` 自动生成）。 |
| `uploads/`  | 用户上传的图片/视频（后端运行时创建）。 |
| `results/`  | 检测输出、报告、训练日志等临时文件夹。 |
| `docker-compose.label-studio.yml` | 启动 Label Studio、PostgreSQL、Redis 的组合环境。 |
| `start.sh` / `stop.sh` | 一键启动/停止 FastAPI、Vite、Celery worker。 |
| `check_env.sh` / `test_services.sh` | 本地自检脚本，确认 Conda、端口等依赖。 |
| `README.md` | 根项目说明，介绍功能概览与快速部署。 |

> **提示**：`logs/`、`uploads/`、`results/` 等目录在运行时自动生成，可在 `start.sh` 中查看初始化逻辑。

## 后端结构（`backend/`）

### `backend/app` 目录拆解

| 子目录 / 文件 | 作用 & 典型内容 |
|---------------|------|
| **`api/v1/`** | REST 端点合集。<br> - `auth.py`：登录/注册、刷新 token；<br> - `admin.py`：用户、模型 CRUD；<br> - `detect.py`：图片/视频检测、仪表盘、历史记录、下载；<br> - `dataset.py`：数据集 CRUD、文件上传、批量检测；<br> - `alerts.py`：告警规则与日志；<br> - `comparison.py`：检测结果对比；<br> - `reports.py`：报告任务管理、PDF/HTML 下载；<br> - `annotations.py`：标注任务、标注记录、导出、导入；<br> - `training.py`：模型训练任务、日志、指标。 |
| **`core/`** | 基础设施。`config.py`/`pydantic-settings` 读取 `.env`；`security.py` 提供 JWT、密码哈希；`cache.py` 定义各类 Redis key 与失效策略（用户仪表盘、模型列表）；`logging.py` 统一 Loguru 日志；`database.py` 按异步模式创建 `AsyncSession`。 |
| **`crud/`** | ORM 封装：`crud_detection_history.py`、`crud_dataset.py`、`crud_alert.py`、`crud_annotation.py`、`crud_training.py` 等，提供分页、过滤、状态更新等操作；API 层仅负责组装参数。 |
| **`models/`** | SQLAlchemy 模型。关键表：`User`、`MLModel`、`DetectionHistory`、`Dataset`/`DataFile`、`BatchJob`、`AlertRule`/`AlertLog`、`Report`、`AnnotationTask`/`Annotation`/`AnnotationExport`、`TrainingJob`、`TrainingMetric`。所有表都有时间戳索引以便统计。 |
| **`schemas/`** | Pydantic v2 Schema，严格定义字段、枚举、分页响应。对前后端契约变更首选查阅该目录。 |
| **`services/`** | 复杂业务逻辑：<br> - `report_generator.py`/`chart_generator.py`/`data_aggregator.py` → 报告数据汇总、绘图、WeasyPrint 导出；<br> - `annotation_converter.py`/`label_studio_service.py` → Label Studio 项目创建、任务导入导出；<br> - `data_preparation.py`/`yolo_trainer.py` → YOLO 训练数据拆分、调用 Ultralytics；<br> - `alert_actions.py` → 邮件/Webhook 通知；<br> - `report_generator.py` 中也负责模板环境、字体配置。 |
| **`tasks/`** | Celery 任务：`detection.py` poll 视频检测状态；`batch_detection.py` 用 chain 顺序处理数据集文件；`report_tasks.py` 负责状态更新 + 生成报告；`training_tasks.py` 负责 GPU worker（`--pool=solo`）启动、训练进度与日志写回。队列、路由策略见 `celery_app.py`。 |
| **`templates/reports/`** | `summary_report.html`、`detailed_report.html`、`comparison_report.html` 三套模板，内嵌 Tailwind 风格 CSS + 图表占位，供 PDF/HTML 输出复用。 |
| **`utils/`** | 文件工具、通用响应体、字典/JSON 转换、坐标归一化等。 |
| **`main.py`** | FastAPI 入口：CORS 配置、路由挂载、`/health` 健康检查。 |

其余重要目录：
- `alembic/` + `alembic.ini`：数据库迁移配置。
- `requirements.txt`：依赖清单（开发/生产一致）。
- `uploads/`、`results/`、`logs/`：运行时数据（若使用 Docker，可映射到宿主机）。
- `docker-compose.label-studio.yml`：提供 Label Studio + PostgreSQL + Redis 组合环境，便于一键启动标注服务。

### 模块关系
- **API 层** → 调用 **CRUD** & **Services**，并触发 **Celery Tasks**。
- **Services** → 负责复杂领域逻辑（报告绘图、Label Studio 同步、YOLO 训练数据准备）。
- **Tasks** → 对耗时操作（视频检测、批量检测、报告、训练）分队列执行，队列在 `celery_app.py` 中统一配置。
- **templates/reports** → 被 `ReportGenerator` 渲染为 HTML，再由 WeasyPrint 导出 PDF。

## 前端结构（`frontend/`）

| 子目录 / 文件 | 作用 |
|---------------|------|
| `api/`        | 所有后端接口的 Axios 封装，包含拦截器（`utils/request.js`）。保持统一的错误处理、blob 下载等。 |
| `views/user/` | 普通用户界面：检测、数据集、告警、报告、标注、仪表盘、首页、Profile 等。 |
| `views/admin/`| 管理后台：Dashboard、UserManagement、ModelManagement、TrainingJobs、CreateTrainingJob、TrainingMonitor 等。 |
| `components/common/` | 可复用组件：`PageHeader`、`StatCard`、`StatusTag`、`EmptyState` 等。 |
| `layouts/AdminLayout.vue` | 管理后台骨架，包括侧边栏、顶栏、用户菜单。 |
| `router/index.js` | 路由表及路由守卫；根据 `meta.requiresAuth` / `requiresAdmin` 控制访问。 |
| `stores/`      | Pinia store，封装 auth/detection 状态及方法。 |
| `assets/styles/` | Tailwind 入口、主题变量、动画等。 |
| `public/`、`dist/` | 静态资源与构建输出。 |

### 关键视图与模块
| 视图/模块 | 说明 |
|-----------|------|
| `views/user/Dashboard.vue` | 用户仪表盘：展示统计卡片、模型使用分布、最新活动。调用 `/detect/dashboard`。 |
| `views/user/Detection.vue` | 单图检测：上传图片、选择模型、实时展示结果。复用了 `stores/detection` 的轮询逻辑。 |
| `views/user/Dataset*` | 数据集列表/详情/批量任务：对应后端 `/datasets`、`/dataset/files`、`/datasets/batch-jobs`。 |
| `views/user/AlertRules.vue` / `AlertLogs.vue` | 告警规则管理、日志查看。 |
| `views/user/Comparison.vue` | 选择多个检测记录进行对比，可从检测历史或报告跳转。 |
| `views/user/Reports.vue` / `ReportGenerator.vue` | 报告任务列表与三步生成器。 |
| `views/user/AnnotationTasks.vue` / `CreateAnnotationTask.vue` / `AnnotationTaskDetail.vue` | 标注任务管理、创建向导、Label Studio 集成。 |
| `views/admin/*` | 管理后台子页面：Dashboard、用户/模型、训练任务等，全部走 `/admin` 路由和专用 API。 |
| `stores/auth.js` | 负责登录态、用户信息、管理员判断；提供 `init`、`login`、`logout`。 |
| `stores/detection.js` | 负责检测进度、轮询、历史数据、可用模型等。 |

### 前端路由关键点
- 所有 `/admin/*` 路由由 `AdminLayout` 包裹，并在 `router.beforeEach` 中校验 `userStore.isAdmin`。
- 用户端 `/annotations/tasks/:id`、`/datasets/:id` 等均通过 Axios API 与对应的后端模块交互。
- 全局状态由 `Pinia` 管理：`auth`（登录态、角色）和 `detection`（历史记录、模型列表、视频轮询）。

## 运行数据与辅助文件

| 目录/文件 | 说明 |
|-----------|------|
| `logs/backend.log` / `logs/celery.log` | API 与 Celery 输出。若发现 5xx / 前端 overlay，可第一时间查看这里。 |
| `uploads/` | 前端上传图片/视频的物理存储，结构为 `uploads/<user_id>/<dataset_id>/文件`。 |
| `results/` | 检测结果（标注图、json）、ZIP 下载、训练日志、报告、批量检测中间件等。 |
| `docs/` | 计划、总结、技术方案、阶段资料。建议 PR 时同步更新相关文档。 |
| `Figures/` | 记录开发阶段遇到的 overlay 截图或需求示意，有助于 bug 复现与分享。 |
| `.service_pids` | `start.sh` 记录的进程 ID（FastAPI/Vite/Celery），`stop.sh` 会读取该文件逐个 kill。 |
| `docker-compose.label-studio.yml` | 默认启动 PostgreSQL、Redis、Label Studio。若本地安装，可在 `.env` 中指向该服务。 |
| `water_detection.db` | 默认 SQLite 数据库。若切换到 PostgreSQL，需更新 `.env` 中 `DATABASE_URL` 并运行 Alembic。 |

## 如何扩展 / 排障
1. **新增 REST API**：在 `app/api/v1` 下创建模块 → 在 `router.py` 注册 → 配套 CRUD / Schema / Service。
2. **新增前端页面**：在 `src/views` 增量开发，并在 `router/index.js` 配置路由及权限。
3. **跟踪异步任务**：Celery 日志 + Redis 队列状态；训练/检测任务会在数据库记录 `status` 与 `log_file_path`。
4. **模板或可视化修改**：报告模板位于 `backend/app/templates/reports`；仪表盘图表在 `frontend/src/views/user/Dashboard.vue` 调整 ECharts 配置。

如需进一步了解技术栈，请参阅《技术栈说明.md》。这两份文档搭配可覆盖 90% 的定位与扩展需求。
