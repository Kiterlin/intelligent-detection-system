### 1. 📋 项目概述 (Project Overview)



**项目名称：** 企业级水下目标智能检测平台

项目目标：

构建一个基于Web的、前后端分离的智能检测系统。该系统不仅为普通用户提供YOLO模型的水下目标检测服务（图像、视频），还为管理员提供一个功能完善的后台管理界面，用于管理用户、模型和系统状态。

**核心特性：**

- **前后端分离：** 易于维护、扩展和独立部署。
- **用户隔离：** 独立的用户登录与权限系统。
- **管理后台：** 对用户和模型资源的可视化管理。
- **模型切换：** 用户（或管理员）可以动态选择使用哪个YOLO模型（v5-v8）进行检测。

### 2. 🏛️ 项目架构设计 (Architecture Design)



我们将采用现代Web服务的经典架构：

- **前端 (Frontend):**
  - **用户界面 (User App):** 用户访问的Web界面（如 `app.yourdomain.com`）。
  - **管理后台 (Admin App):** 独立的管理员登录和管理界面（如 `admin.yourdomain.com`）。
  - *（或者，也可以合并在一个前端项目中，通过路由和权限区分）*
- **后端 (Backend):**
  - **API服务器:** 一个RESTful API服务器，处理所有业务逻辑、数据库交互和模型调用。
- **数据库 (Database):**
  - 一个关系型数据库，用于存储用户信息、模型元数据、检测历史等。
- **模型服务 (Model Service):**
  - 后端API服务器将**直接加载和运行**PyTorch和YOLO模型。对于大流量，未来可以将其拆分为独立的微服务。

### 4. 🧩 功能模块拆解 (Functional Modules)



我们将系统分为三个主要部分：



#### A. 通用模块



1. **用户认证系统 (Auth)**
   - **登录页面 (`/login`)：** 用户名/密码登录，生成JWT Token。
   - **注册页面 (`/register`)：** (可选，或仅限管理员创建)
   - **JWT 令牌刷新：** 自动刷新令牌，保持登录状态。
   - **路由守卫 (Frontend)：** 检查用户是否登录以及其角色（`user` / `admin`）。



#### B. 用户页面 (User View)



1. **系统首页/仪表盘 (`/`)**
   - 显示系统简介、可用的模型列表、个人检测历史统计。
2. **目标检测服务 (`/detect`)**
   - **模型选择：** 下拉框选择已激活的YOLO模型。
   - **图片检测：** 上传图片 -> 后端处理 -> 返回带标注的图片或JSON结果。
   - **视频检测：**
     - 上传视频文件。
     - **[关键]** 后端应**异步处理**视频（例如使用 Celery + RabbitMQ/Redis 作为任务队列）。
     - 前端轮询或使用WebSocket等待处理结果，完成后提供下载链接。
   - **(可选) 实时检测：** 允许输入RTSP流地址或使用Webcam，后端处理后通过WebSocket实时回传检测流。
3. **检测历史 (`/history`)**
   - 列表形式展示该用户所有的检测记录（时间、使用模型、输入、结果）。
4. **个人中心 (`/profile`)**
   - 修改密码。



#### C. 管理后台 (Admin View)



- *此部分对普通用户不可见，需要 `admin` 角色登录。*

1. **系统看板 (`/admin/dashboard`)**
   - 展示核心指标：总用户数、模型数、今日检测次数、服务器状态。
2. **用户管理 (`/admin/users`)**
   - **列表：** 显示所有用户（ID、用户名、角色、注册时间）。
   - **操作：**
     - **创建用户** (手动添加新用户)。
     - **编辑用户** (修改用户信息，如重置密码、设置角色 `user` <-> `admin`)。
     - **删除用户**。
3. **模型管理 (`/admin/models`)**
   - **列表：** 显示所有已上传的YOLO模型（名称、版本、描述、文件路径、上传时间）。
   - **操作：**
     - **上传模型：** 上传新的 `.pt` 权重文件，并填写模型名称、版本、描述。
     - **激活/禁用：** 控制模型是否在用户端的“模型选择”下拉框中可见。
     - **删除模型：** 从文件系统和数据库中移除模型。

### 5. Database 数据库设计 (E-R Model)



建议至少包含以下三个核心表：

1. **`users` (用户信息表)**
   - `id` (Int, Primary Key)
   - `username` (String, Unique, Not Null)
   - `hashed_password` (String, Not Null)
   - `email` (String, Unique)
   - `role` (Enum: 'user', 'admin', Default: 'user')
   - `created_at` (DateTime)
2. **`ml_models` (模型信息表)**
   - `id` (Int, Primary Key)
   - `model_name` (String, Not Null)
   - `version` (String)
   - `description` (Text)
   - `file_path` (String, Not Null) - *服务器上 `.pt` 文件的相对路径*
   - `is_active` (Boolean, Default: True) - *是否对用户可见*
   - `uploaded_by_user_id` (Int, Foreign Key -> `users.id`)
   - `uploaded_at` (DateTime)
3. **`detection_history` (检测历史表)**
   - `id` (Int, Primary Key)
   - `user_id` (Int, Foreign Key -> `users.id`)
   - `model_id` (Int, Foreign Key -> `ml_models.id`)
   - `input_type` (Enum: 'image', 'video')
   - `input_file_path` (String) - *用户上传文件的路径*
   - `output_file_path` (String) - *检测结果的路径*
   - `status` (Enum: 'pending', 'processing', 'completed', 'failed')
   - `detected_at` (DateTime)

### 7. 📜 项目构建与开发规范



1. **版本控制 (VCS):**

   - 使用 **Git**。

   - **仓库结构：** 推荐使用 **Monorepo**（单一仓库），结构如下：

     ```
     /YOLO-Platform/
     |-- /backend/      (FastAPI, SQLAlchemy, PyTorch...)
     |-- /frontend/     (Vue.js, Element Plus...)
     |-- /docs/         (文档)
     |-- .gitignore
     |-- docker-compose.yml
     |-- README.md
     ```

2. **环境管理：**

   - **后端：** 使用 `venv` 或 `conda` 虚拟环境。`requirements.txt` 必须包含所有依赖。
   - **前端：** 使用 `npm` 或 `yarn`。`package.json` 锁定依赖。

3. **配置管理：**

   - **严禁**将敏感信息（如数据库密码、JWT密钥）硬编码在代码中。
   - 所有配置项应通过 **环境变量** 或 `.env` 文件注入。

4. **代码风格：**

   - **后端 (Python):** 遵循 **PEP 8**。使用 **Black** 自动格式化，**Flake8** 进行代码检查。
   - **前端 (JavaScript/Vue):** 使用 **ESLint** 和 **Prettier** 强制统一代码风格。

5. **开发流程：**

   - 采用 `git-flow`（或简化版），`main` 分支为生产分支，`dev` 为开发主分支，新功能开发应使用 `feature/` 分支。
   - 提交代码前必须在本地运行通过所有Linter和（如果有）单元测试。

### 8. 🚀 部署方案 (Production Deployment)



推荐使用 **Docker Compose** 进行一体化部署：

1. **`docker-compose.yml`** 文件将编排三个服务：
   - **`frontend` (Nginx):** 一个Nginx容器，用于提供编译后的前端静态文件。
   - **`backend` (Python):** Uvicorn/Gunicorn 运行 FastAPI 应用的容器。
   - **`db` (PostgreSQL):** 官方的 PostgreSQL 镜像，数据卷挂载到宿主机。
2. **`nginx.conf` (Nginx 配置):**
   - 配置反向代理。
   - `location /` 指向 `frontend` 服务的静态文件。
   - `location /api/` 代理到 `backend` 服务的API端口（如 `http://backend:8000`）。
3. **文件存储：**
   - 用户上传的文件和检测结果，应存储在挂载到宿主机的卷（Volume）中，或使用云存储（如 AWS S3）。
