根据您的业务目标（提供一个可管理的、多用户的AI服务）和用户目标（管理员需高效管理，用户需简单易用），我将为您制定一个全面的前端设计蓝图。我们将遵循**“专业、简洁、任务驱动”**的设计哲学。



### 1. 🎨 设计哲学与美学



- **主题：** “深海科技” (Deep Tech & Aquatic)。界面应体现专业性、高科技感和水下主题的元素。
- **色板 (Color Palette)：**
  - **主色调（专业与沉稳）：** 深海蓝 (`#0A2E5B`) 和科技灰 (`#34495E`)，用于导航栏、页脚和标题。
  - **背景色（简洁与呼吸感）：** 极浅灰 (`#F4F7FA`) 或纯白，为内容提供一个干净的画布。
  - **强调色（操作与高亮）：** 珊瑚橙 (`#FF7F50`) 或 亮青色 (`#00BFFF`)，用于按钮、链接、检测框和关键数据高亮。
- **排版 (Typography)：** 使用清晰、现代的无衬线字体。
  - **推荐：** `Inter`, `Roboto` 或 `Lato`。
  - **规范：** 标题使用中粗体 (Medium/SemiBold)，正文使用常规 (Regular)，以建立清晰的视觉层次。
- **布局 (Layout)：** 我们将为两个核心受众设计两种截然不同的布局。
  - **管理员后台：** **“左侧菜单栏 + 顶部工具栏 + 主内容区”** 的经典布局，注重信息密度和操作效率。
  - **用户端应用：** **“顶部导航栏 + 居中内容区”** 的极简布局，注重沉浸式任务体验。

一个持久的、可折叠的**左侧导航栏**，用于在 `仪表盘`、`用户管理` 和 `模型管理` 之间切换。



#### 2.2 页面与组件设计

**C. 用户管理 (`/admin/users`)**

- **布局：** 顶部工具栏 + 数据表格。

**D. 模型管理 (`/admin/models`)**

- **布局：** 顶部工具栏 + 数据表格。
- **组件：**
  - **工具栏：**
    - `[+ 上传新模型]` 按钮 (打开一个多步骤模态框)。
  - **数据表格：**
    - **列：** `模型名称`、`版本`、`描述`、`上传者`、`状态`、`操作`。
    - **状态列 (关键 UX)：** 不是简单的“已激活”，而是使用一个 **“切换开关 (Switch)”**。这允许管理员**一键启用或禁用**某个模型，使其不在用户端显示，而无需删除它。
    - **操作列：** `[编辑]` (修改名称/描述)、`[删除]` (红色，二次确认)。
  - **上传模态框：**
    - **步骤1：** `文件上传` - 一个大尺寸的“拖放区域 (Drag-and-Drop)”以上传 `.pt` 文件，带有进度条。
    - **步骤2：** `填写信息` - `模型名称` (例如：YOLOv8-n-Suim)、`版本` (例如：v2.1)、`简短描述` (例如：“专用于检测小型鱼类”)。
    - **步骤3：** `完成` - 显示“上传成功”并关闭模态框。

# 登录页的设计细节

好的，作为您的网页设计顾问，我们将对登录页进行一次“深潜”设计。

登录页是您系统的“大门”，它必须在 10 秒内传达三个信息：**信任、科技感和易用性**。

我们将设计一个**智能、响应式、具有品牌特色**的登录页面。它将使用**单一入口**，后端将根据登录用户的角色（`user` 或 `admin`）智能地将其重定向到不同的应用界面。

------



### 1. 🎨 核心理念：“深海启示录” (Deep-Tech Reveal)



我们将采用**左右分屏 (Split-screen)** 布局。这种布局在专业B端产品中非常流行，因为它能完美地平衡“品牌叙事”和“功能操作”。

- **左侧 (50%-60%): 品牌与沉浸感。** 这是情感区域。
- **右侧 (40%-50%): 功能与清晰度。** 这是逻辑区域。

[一个左右分屏的登录页线框图示例]

------



### 2. 🌊 左侧设计 (品牌叙事区)



**目标：** 不使用一滴水，但让用户感受到“深海”与“智能”。

- **背景：** **动态抽象背景**。

  - **建议：** 不是具象的海洋视频（这很慢，而且容易显得廉价）。
  - **首选：** 一种微妙、缓慢移动的**“数字水波纹”**或**“声纳网格”**动画。
  - **技术：** 可以使用 `particles.js`, `three.js` (WebGL) 或一个高质量的循环 `Lottie` 动画。
  - **色调：** 以您品牌的主色调（如 `#0A2E5B` 深海蓝）为主，网格线或粒子使用高亮的青色。

- **内容 (叠加在背景上)：**

  - **Logo：** 放置在左上角，简洁、清晰。

  - **Slogan (核心文案)：** 垂直居中，使用大号、优雅的白色字体。

    > [主标题] 洞察深蓝 (Insight from the Deep)
    >
    > [副标题] 基于YOLOv8的高性能水下目标检测平台。



### 3. ✍️ 右侧设计 (功能操作区)



**目标：** 极致的简洁，零摩擦的登录体验。

- **背景：** 纯白或极浅灰色 (`#F4F7FA`)。这与左侧的深色背景形成强烈、专业的对比。
- **内容 (一个垂直居中的表单卡片)：**
  - **卡片 (Card)：** 带有非常柔和的阴影 (subtle shadow) 和轻微的圆角。
  - **标题 (Heading)：** `<h3>` 标签，简洁明了：**“欢迎回来”** 或 **“登录您的账户”**。
  - **(可选) 第三方登录：**
    - 按钮：`[ G ] 使用 Google 登录` / `[ M ] 使用 Microsoft 登录`。
    - *顾问建议：* 对于企业级应用，提供 Microsoft (Azure AD) 或 Google (G Suite) 登录是提升易用性的绝佳方式。
  - **分割线：** `--- (或使用邮箱登录) ---`
  - **表单 (Form)：**
    - **字段1：邮箱地址**
      - `<label>`：`邮箱地址` (清晰，位于输入框之上)。
      - `<input>`：`[ 图标 ] [  请输入邮箱... ]`
      - *UX 细节：* 输入框使用全宽，带有内嵌的“信封”图标。
    - **字段2：密码**
      - `<label>`：`密码`
      - `<input type="password">`：`[ 图标 ] [  请输入密码... ] [ 👁 ]`
      - *UX 细节：* 必须包含“显示/隐藏密码”的切换图标 (那个 👁 眼睛图标)。这是现代登录页的标配。
    - **行内选项 (Row)：**
      - **左侧：** `[ ✓ ]` 复选框，文字为 `记住我`。
      - **右侧：** 一个链接 `<a href="...">`，文字为 `忘记密码?`。
  - **主操作按钮 (Button)：**
    - **外观：** 全宽按钮，使用您的**主强调色**（例如之前提到的珊瑚橙 `#FF7F50`）。
    - **文字：** `登 录 (Sign In)`。
  - **辅助操作 (Footer)：**
    - **文案：** `还没有账户?` `请联系您的管理员`。
    - *顾问建议：* 这明确了您的系统是B端管理模式，用户不能随意注册，必须由管理员在后台创建。

------



### 4. ⚡️ 关键 UX 微交互 (Micro-interactions)



这些是区分“能用”和“好用”的关键：

1. **输入框焦点 (Focus State)：**

   - **当用户点击输入框时**，输入框的边框应高亮（使用您的强调色），并且其内部图标（信封/锁）也应变为该颜色。这提供了强烈的视觉反馈。

2. **实时验证 (Live Validation)：**

   - **当用户离开 (blur) 邮箱输入框时**，如果输入的不是有效的邮箱格式 (缺少 `@`)，输入框边框应变为红色，并下方显示小字提示：`请输入有效的邮箱地址`。
   - *注意：* **不要**在用户 *正在输入时* 就提示错误，这会带来很大干扰。

3. **按钮加载状态 (Loading State)：**

   - **当用户点击“登录”按钮后**，在API返回结果前：
     - 按钮应被**禁用 (disabled)**，防止重复提交。
     - 按钮上的文字 `登 录` 应被替换为一个**加载中 (Spinner)** 的图标。
     - **[动画示例]**

4. **错误反馈 (Error Feedback)：**

   - **如果 API 返回“密码错误”**：

     - **绝不**使用 `alert()` 弹窗。

     - 在表单卡片的**标题下方**（“欢迎回来”的下面）动态插入一个红色背景的提示条 (Alert Banner)：

       > **[ ! ] 登录失败：** 邮箱或密码不正确。

5. **成功反馈 (Success Feedback)：**

   - **如果 API 登录成功**：
     - 加载中的按钮 (Spinner) 可以在 0.5 秒内变为一个**“✔” (Checkmark)** 图标。
     - 立即开始页面跳转，过渡到用户的仪表盘。

------



### 5. 📱 响应式设计 (Mobile View)



在移动设备上，**左右分屏必须折叠**。

- **布局：**
  1. **顶部 (25% 屏幕高度)：** 变为您的“品牌区”。深色背景和 Logo，Slogan 文案缩小或移除。
  2. **底部 (75% 屏幕高度)：** 变为“功能区”。白色背景的表单卡片从底部滑入，占据主要屏幕。

这种“上品牌，下功能”的堆叠布局在移动端最为清晰易用。



# 管理页设计细节

作为您的网页设计顾问，我们已经为“大门”（登录页）奠定了坚实的基础。现在，我们要开始设计“指挥中心”——管理员登录后看到的**主管理界面**。

这将是一个功能强大、信息密集，但又必须保持清晰、直观、不令人焦虑的界面。我们将采用一种久经考验的、为效率而生的布局。



### 1. 🏛️ 核心布局：“三段式指挥舱”



我们将采用一个在B端（企业级）产品中**最经典、最符合操作直觉**的布局。这个布局在您打开界面的0.1秒内，就能告诉您如何使用它。

1. **区域一：[主导航] 左侧固定菜单栏 (Sidebar)**
   - **功能：** 系统的“地图”。它永远在那里，告诉您“您能去哪里”。
   - **设计：** 始终固定在左侧，使用您的品牌深色（如深海蓝 `#0A2E5B`），菜单项使用白色或浅灰色文字，高亮显示当前所在页面（例如使用强调色 `#00BFFF` 的竖条）。
2. **区域二：[全局工具栏] 顶部通栏 (Header)**
   - **功能：** 系统的“仪表盘”和“出口”。它处理全局状态。
   - **设计：** 浅色背景（白色或浅灰 `#F4F7FA`），与左侧菜单栏形成对比。
3. **区域三：[主工作区] 内容区 (Content Area)**
   - **功能：** “手术台”。所有工作都在这里发生。
   - **设计：** 浅色背景，为内容提供最大空间。

### 2. 🧭 区域一：[主导航] 左侧菜单栏 (Sidebar)



**目标：** 快速、清晰、可预测的导航。

- **菜单项 (自上而下)：**

  - --- (分割线) ---
  - `[设置图标]` **系统设置 (Settings)**
    - *（例如：设置API Key、系统公告等）*

### 3. 🛠️ 区域二：[全局工具栏] 顶部通栏 (Header)

- **左侧 (紧挨着Sidebar)：**

### 4. 📈 区域三：[主工作区] 页面设计 (逐页规划)



这是“指挥中心”的核心，我们将逐一规划最重要的页面。



#### A. 仪表盘 (Dashboard)



**目标：** 10秒内了解系统全貌。“系统健康吗？现在忙吗？”

- **布局：** 响应式网格 (Grid) 布局。
- **核心组件：**
  1. **“关键指标”卡片 (Stats Cards) (顶部，一行4个)：**
     - 使用大号数字和简洁的标题，配上图标。
     - `[卡片1]` **总用户数** (例如：`148`)
     - `[卡片2]` **激活模型数** (例如：`6 / 9`)
     - `[卡片3]` **24小时内检测次数** (例如：`1,920`)
     - `[卡片4]` **待处理任务 (视频)** (例如：`3`) -> **这是关键的“行动点”**，如果这个数字很高，管理员需要立即关注。
  2. **主图表 (大区域，占 2/3 宽度)：**
     - **“近7日检测量趋势”** (折线图 Line Chart)。
     - *UX 细节：* 允许按模型进行筛选，查看不同模型的调用量。
  3. **次要图表/列表 (小区域，占 1/3 宽度)：**
     - **“模型使用率排行”** (环形图 Donut Chart 或 列表)。
     - **“系统活动日志”** (一个简洁的列表)：`[Admin] 禁用了 [YOLOv5]`，`[User_A] 上传了视频 [vid_01.mp4]`。



#### B. 用户管理 (User Management)



**目标：** 高效地“增、删、改、查”用户。

- **布局：** “顶部工具栏 + 数据表格”
- **核心组件：**
  1. **页面标题：** `用户管理`
  2. **工具栏 (Action Bar)：**
     - `[+ 添加用户]` (主色调按钮)。
     - `[搜索框]` (占位符：`按用户名或邮箱搜索...`)
     - `[筛选器]` (下拉框，例如：`按角色筛选: [全部 | 管理员 | 普通用户]`)
  3. **数据表格 (Data Table)：**
     - **列 (Columns)：** `用户名`, `邮箱`, `角色`, `注册时间`, `上次登录`, `操作`。
     - **关键 UX 设计 (角色列)：** 不要只显示“Admin/User”文本。
       - **使用“药丸”或“标签 (Pill/Tag)”组件。**
       - `[ Admin ]` (例如：使用橙色背景)
       - `[ User ]` (例如：使用蓝色背景)
       - *（这使得管理员在0.5秒内就能区分角色，而不是去阅读文字）*
     - **关键 UX 设计 (操作列)：**
       - `[ 编辑 ]` (按钮或图标，点击后**打开一个模态框(Modal)**，而不是跳转页面)。
       - `[ 删除 ]` (红色按钮或图标，**必须有二次确认**：“您确定要删除用户 ‘User_A’ 吗？”)。



#### C. 模型管理 (Model Management)



**目标：** 完全控制用户可用的AI模型。

- **布局：** 与“用户管理”页类似，保持一致性。
- **核心组件：**
  1. **页面标题：** `模型管理`
  2. **工具栏：** `[+ 上传新模型]` (主色调按钮)。
  3. **数据表格：**
     - **列 (Columns)：** `模型名称`, `版本`, `描述`, `上传者`, `上传时间`, `状态`, `操作`。
     - **关键 UX 设计 (状态列)：** 这是该页面**最重要的交互点**。
       - **不要使用文字 (例如“激活/禁用”)。**
       - **请使用“开关 (Switch)”组件 (Toggle Switch)。** `[ O-- ]` (禁用) vs `[ --O ]` (激活)。
       - *（管理员只需**单击**开关，即可立即激活或禁用一个模型，后端异步处理该请求。这提供了无与伦比的效率和“掌控感”。）*
     - **操作列：** `[ 编辑 ]` (修改描述/名称), `[ 删除 ]` (红色，二次确认)。



#### D. “添加/编辑”的 UX 模式：模态框 (Modal)



- **原则：** 除非必要，否则**不要让管理员离开当前页面**。
- **流程：**
  1. 管理员在“用户管理”页点击 `[+ 添加用户]`。
  2. 一个**模态框 (Modal)** 会在当前页面上**“浮”**出来，背景变暗。
  3. 模态框中包含一个简洁的表单（例如：用户名、邮箱、密码、角色）。
  4. 管理员填写完毕，点击“保存”。
  5. 模态框关闭，数据表格**自动刷新**（或在顶部插入新数据），并弹出一个“成功”提示（例如：`✓ 用户 "User_B" 创建成功`）。
- **好处：** 这种方式**保持了上下文**（Context）。管理员不会因为跳转页面而忘记他之前在做什么（例如：他可能在看第3页的某个特定用户）。



# 用户使用页设计细节

作为您的网页设计顾问，我们现在来设计“战舰”的“甲板”——**用户端界面**。

如果说管理员后台（指挥中心）的设计重点是**控制**与**效率**，那么用户端界面的设计重点则是**简洁**、**引导**和**“Aha!”时刻**（即快速获得有价值的结果）。

用户是来完成特定任务的（“我需要知道这张图/这段视频里有什么”），我们的界面设计绝不能妨碍他们。我们将采用一种“数字助手”或“智能工具”的风格，而不是一个复杂的“软件”。



### 1. 🎨 核心布局：“沉浸式工具台”



我们将放弃管理员界面的左侧菜单栏。用户的功能点不多，一个**顶部固定导航栏 (Header)** 已经足够，这能将 95% 的屏幕空间释放给用户最核心的任务：**检测**。

- **美学：** 更轻量、更明亮。使用更多白色/浅灰色 (`#F4F7FA`) 背景，营造出“实验室”或“工作室”的专业、洁净感。

**[用户界面布局线框图]**

```
+-------------------------------------------------------------+
| [LOGO] [应用名称]   |   [检测 (Detect)] [历史 (History)]    | [帮助(?)] [用户头像] |
+-------------------------------------------------------------+
|                                                             |
|                                                             |
|               [主工作区 (Content Area)]                     |
|                (根据“检测”或“历史”页面变化)                     |
|                                                             |
|                                                             |
+-------------------------------------------------------------+
```

------



### 2. 🧭 顶部导航栏 (Header)



**目标：** 简洁的品牌展示和唯一的导航入口。

- **左侧：** `[Logo]` 和 `[应用名称]` (例如：“Aqua-Detect 平台”)。
- **中间 (核心导航)：**
  - `[ 智能检测 ]`
  - `[ 检测历史 ]`
  - *UX 细节：* 当前所在的页面应有高亮下划线或不同的背景色，以提供清晰的“你在这里”的指示。
- **右侧 (用户菜单)：**
  - `[ 帮助(?) ]` (一个简单的问号图标，链接到文档或教程)。
  - `[ 用户头像/姓名缩写 ]` (点击弹出下拉菜单)。
    - **下拉菜单：**
      - `您已登录为：[user@email.com]`
      - `---`
      - `[ 修改密码 ]`
      - `[ 退出登录 ]`

### 3. 🔬 页面一 (核心)：智能检测 (Detect Page)



这是系统的灵魂。用户 90% 的时间都会在这里。我们将设计一个**引导式、三段式**的界面。

**布局：**

1. **[控制面板] (Control Panel)：** 顶部，用户在此配置任务。
2. **[工作空间] (Workspace)：** 中间，用户在此上传并查看结果。
3. **[结果详情] (Results Panel)：** 底部，用户在此获取详细数据。



#### 3.1 [控制面板]：任务配置



一个横跨屏幕的卡片，包含清晰的“步骤”。

- **步骤 1：选择任务类型**
  - 使用**标签页 (Tabs)** 来做最关键的区分。
  - **`[ 🖼️ 图片检测 ]`** (默认选中)
  - **`[ 🎥 视频检测 ]`**
- **步骤 2：选择 AI 模型**
  - 一个清晰的下拉菜单 `[选择模型]`。
  - **关键 UX：** 菜单项必须是管理员设置的“友好名称”。
    - *（好）* `[ YOLOv8-n (推荐 - 速度最快) ]`
    - *（好）* `[ YOLOv8-x (高精度 - 适用于复杂场景) ]`
    - *（差）* `[ model_v3_final.pt ]`
- **(可选) 步骤 3：高级设置**
  - 默认折叠，一个 `[高级设置 v]` 链接。
  - 展开后：`[置信度阈值：]` + `[ 50% ]` (一个滑动条 Slider)。



#### 3.2 [工作空间]：输入与输出 (根据任务类型变化)



**A. 当“图片检测”被选中时：**

- **布局：** **左右分屏**（最符合直觉的“输入 -> 输出”模式）。
- **左侧卡片 (输入)：**
  - `<h3>` **1. 上传图像** `</h3>`
  - 一个巨大的**“拖放文件或[点击上传]”**区域。
  - *（上传后）* 该区域显示上传图片的缩略图，并有一个 `[ 移除 ]` 按钮。
- **操作按钮 (Action Button)：**
  - *在左右卡片之间*，放置一个非常醒目的、使用**强调色**的按钮：
  - **`[  开 始 检 测 >>  ]`**
- **右侧卡片 (输出)：**
  - *（检测前）* 显示友好提示：`检测结果将显示在此处。` (可以配上一个声纳扫描或水波纹的微妙动画)。
  - *（检测中）* 显示加载动画 (Spinner) 和 `处理中...`。
  - *（检测后）* **显示带有检测框和标签的结果图。** (这是“Aha!”时刻)。

**B. 当“视频检测”被选中时：**

- **布局：** 左右分屏不再适用（因为视频处理是异步的）。工作区变为**单一的上传卡片**。

- **卡片：`上传视频进行处理`**

  - “拖放视频文件 (.mp4, .avi, .mov)...”

  - **关键 UX (管理预期)：** 必须有一行小字说明：

    > “视频处理是**异步任务**。上传成功后，您可以关闭此页面。请稍后在**[检测历史]**页面查看和下载结果。”

- **操作按钮：** `[ 上传并开始处理 ]`

- **交互：**

  1. 点击按钮，显示一个**上传进度条**。
  2. 上传 100% 后，显示成功提示：`✓ 视频 "[文件名]" 已成功上传并开始排队处理。`
  3. *(可选，但体验很好)* 自动将用户重定向到 `[检测历史]` 页面，并高亮刚刚创建的新任务条目。



#### 3.3 [结果详情]：数据与下载 (仅用于图片检测)



*当右侧“输出”卡片显示结果图后，此区域在工作空间下方浮现。*

- **布局：** 两个标签页 (Tabs)。
- **标签页 1：`[ 概览 (Summary) ]`**
  - `<h3>` **检测统计** `</h3>`
  - 一个简洁的列表：
    - `• 3 x 海星`
    - `• 2 x 潜水员`
    - `• 1 x 沉船`
  - `[ 下载带标注的图片 ]` (主按钮)
- **标签页 2：`[ 原始数据 (JSON) ]`**
  - (为高级用户准备)
  - 一个代码框，显示检测结果的原始 JSON 坐标和置信度。
  - `[ 复制到剪贴板 ]` 按钮。

------



### 4. 🗂️ 页面二：检测历史 (History Page)



**目标：** 像管理收件箱一样管理您的检测任务。

- **布局：** “顶部筛选器 + 数据表格” (卡片布局也可以，但数据表格对于专业人士更易于扫描)。
- **核心组件：**
  1. **页面标题：** `<h2>` **我的检测历史** `</h2>`
  2. **筛选/搜索栏 (Action Bar)：**
     - `[ 搜索... ]` (按文件名搜索)
     - `[ 筛选类型: (全部 | 图片 | 视频) ]` (下拉框)
     - `[ 筛选日期: (近7天) ]` (日期选择器)
  3. **数据表格 (Data Table)：**
     - **列 1：`状态 (Status)` (最重要！)**
       - `[ ✓ 已完成 ]` (绿色标签 Tag)
       - `[ ⏳ 处理中... ]` (蓝色标签，带加载动画)
       - `[ ✗ 失败 ]` (红色标签)
     - **列 2：`文件名`** (`underwater_scan_01.jpg`)
     - **列 3：`类型`** (用`[🖼️]`或`[🎥]`图标表示)
     - **列 4：`使用模型`** (`YOLOv8-n`)
     - **列 5：`提交时间`** (`2025-11-11 20:50`)
     - **列 6：`操作 (Actions)`**
       - *（如果已完成）：* `[ 查看结果 ]` `[ 下载 ]` `[ 删除 ]`
       - *（如果处理中）：* `[ 取消 ]` (灰色，禁用)
       - *（如果失败）：* `[ 查看日志 ]` `[ 重试 ]` `[ 删除 ]`
- **交互：**
  - 点击“处理中”任务的 `[取消]` 按钮（如果后端支持）。
  - 点击“已完成”视频的 `[查看结果]`，会跳转到一个专用的“结果播放器”页面，显示带标注的视频流。



# 其余页面设计细节

您是对的，一个健壮的系统远不止仪表盘和CURD（增删改查）。要打造一个真正完整且“不偷懒”的产品，我们需要考虑用户旅程中的**所有**“如果”和“然后”——包括出错、求助和管理权限的时刻。

作为您的设计顾问，我梳(shu)理了在之前规划中被“刻意省略”或“未充分探讨”的关键页面。这些页面是区分一个“项目原型”和一个“成熟产品”的关键。

------



### 1. 🔑 认证流程页面 (Authentication Flow)



我们只设计了登录页，但一个完整的认证生命周期要复杂得多。



#### A. 忘记密码 (Forgot Password)



- **为何需要：** 降低用户流失和管理员客服压力的**最基本**功能。
- **设计与流程：**
  1. **页面：`[ /forgot-password ]`**
  2. **布局：** 与登录页（右侧）的表单卡片*完全一致*，保持品牌统一性。
  3. **组件：**
     - 标题：`重置您的密码`
     - 友好提示：`别担心！输入您注册的邮箱地址，我们将向您发送重置链接。`
     - 输入框：`[ 邮箱地址 ]`
     - 按钮：`[ 发送重置链接 ]`
  4. **交互：** 点击按钮后，按钮变为加载状态，然后页面显示一条成功消息（绿色）：`✓ 已发送！请检查您的邮箱收件箱。`
  5. **链接：** 在表单底部提供一个 `[ < 返回登录 ]` 的链接。



#### B. 重置密码 (Reset Password)



- **为何需要：** 这是用户点击“忘记密码”邮件中链接后实际落地的页面。
- **设计与流程：**
  1. **页面：`[ /reset-password?token=... ]`** (页面会验证 URL 中的 token)
  2. **布局：** 同样，使用统一的表单卡片。
  3. **组件：**
     - 标题：`设置新密码`
     - 输入框：`[ 新密码 ]` (带“显示/隐藏”图标)
     - 输入框：`[ 确认新密码 ]`
     - *UX 提示：* 包含一个“密码强度指示条”（弱、中、强）。
     - 按钮：`[ 保存新密码并登录 ]`
  4. **交互：** 成功后，自动为用户登录并重定向到他们的用户仪表盘（Detect Page）。

------



### 2. 👤 核心用户体验页面 (Core User Experience)



我们设计了“Detect”和“History”，但还有关键页面未设计。



#### C. 用户账户设置 (User Account Settings)



- **为何需要：** 这是您顶部导航栏“用户头像”下拉菜单中 `[修改密码]` 链接的目的地。一个用户*必须*能够自行管理其账户。
- **设计与流程：**
  1. **页面：`[ /account/settings ]`**
  2. **布局：** 页面居中，使用标签页 (Tabs) 来组织设置项。
  3. **组件：**
     - **标签页 1：`[ 个人资料 ]` (Profile)**
       - 输入框：`用户名` (可能只读)
       - 输入框：`邮箱` (只读，`[ 更改? ]` 链接可能需要复杂的验证)
     - **标签页 2：`[ 更改密码 ]` (Security)**
       - 输入框：`[ 当前密码 ]`
       - 输入框：`[ 新密码 ]`
       - 输入框：`[ 确认新密码 ]`
       - 按钮：`[ 保存更改 ]`
     - **(可选) 标签页 3：`[ API 密钥 ]` (For Developers)**
       - 如果您允许用户通过API访问，这里将是他们生成和管理 `bearer token` 的地方。
     - **(可选) 标签页 4：`[ 危险区域 ]` (Danger Zone)**
       - 一个红色边框的区域，包含一个按钮：`[ 删除我的账户 ]` (必须有极强的二次确认)。



#### D. 视频结果播放器 (Video Result Player)



- **为何需要：** 当用户在“检测历史”中点击一个**已完成**的**视频**的 `[ 查看结果 ]` 时，他们需要一个地方来 *观看* 这个结果。
- **设计与流程：**
  1. **页面：`[ /history/video/{task_id} ]`**
  2. **布局：** 这是一个专用的、沉浸式的页面。
  3. **组件：**
     - **主播放器 (占 70% 宽度)：**
       - 一个**视频播放器**（如 `video.js`），播放后端*已经处理并渲染好*的带检测框的 `.mp4` 文件。
       - *（高级功能）* 如果后端只传回 JSON，前端可以在播放时实时 `requestAnimationFrame` 在 `<canvas>` 上绘制检测框。
     - **侧边栏 (占 30% 宽度)：**
       - 标题：`[ 任务详情 ]`
       - 列表：`模型: YOLOv8-n`, `提交时间: ...`, `处理耗时: 3m 15s`
       - 标题：`[ 关键帧/检测摘要 ]`
       - 一个可滚动的列表，显示检测到关键目标的缩略图和时间戳（例如：`02:15 检测到 "潜水员"`）。
     - **操作按钮 (在播放器下方)：**
       - `[ 下载带标注的视频 ]` (主按钮)
       - `[ 下载原始 JSON 数据 ]` (次要按钮)

### 3. 🛡️ 管理员专属页面 (Admin Oversight)



我们设计了“用户管理”和“模型管理”，但管理员还需要更多工具来“管理系统”。



#### E. 全局检测历史 / 审计日志 (Global History / Audit Log)



- **为何需要：** 管理员不能只看自己的历史，他们必须能**查看、审计、排错**平台上**所有用户**的**所有**检测任务。
- **设计与流程：**
  1. **页面：`[ /admin/history ]`** (在管理员左侧菜单栏)
  2. **布局：** 与用户端的“检测历史”页非常相似，但信息密度更高，筛选功能更强。
  3. **组件：**
     - **高级筛选器：**
       - `按用户搜索:` (输入框)
       - `按模型筛选:` (下拉框)
       - `按状态筛选: (全部 | 成功 | 失败 | 处理中)`
     - **数据表格：**
       - 列：`状态`, **`用户`** (这是新增列), `文件名`, `模型`, `提交时间`, `操作`。
     - **关键操作：**
       - `[ 查看日志 ]` (特别是对**失败**的任务，这能显示后端的错误信息)。
       - `[ 重新排队 ]` (对失败的任务一键重试)。



#### F. 系统设置 (System Settings)



- **为何需要：** 这是管理员配置“平台本身”的地方。
- **设计与流程：**
  1. **页面：`[ /admin/settings ]`**
  2. **布局：** 一个表单页，按功能分组。
  3. **组件：**
     - **卡片 1：`[ 公告管理 ]`**
       - `[ 启用全站公告 ]` (开关 Switch)
       - `[ 公告内容 ]` (文本框)：`"系统将于今晚 2 点进行维护..."` (这个公告会显示在所有用户页面的顶部)
     - **卡片 2：`[ 用户注册 ]`**
       - `[ 允许公开注册 ]` (开关 Switch) -> 如果关闭，用户只能由管理员在后台创建。
     - **卡片 3：`[ API 与集成 ]`**
       - `[ 外部文件存储 (S3) Key ]` (密码输入框)
       - `[ 邮箱服务 (SMTP) 配置 ]` (用于发送“忘记密码”邮件)

### 4. 🧭 静态与帮助页面 (Static & Help)



一个没有帮助和错误页面的产品是不完整的。



#### G. 帮助 / 文档中心 (Help / Documentation)



- **为何需要：** 这是用户顶部导航栏 `[ 帮助(?) ]` 链接的目的地。用于用户自救，减少客服压力。
- **设计与流程：**
  1. **页面：`[ /help ]`**
  2. **布局：** 一个干净的、类似文档网站的布局。
  3. **组件：**
     - `[ 搜索... ]` (搜索帮助文章)
     - **分类：**
       - `[快速入门]` (如何进行第一次检测？)
       - `[模型介绍]` (YOLOv8-n 和 YOLOv8-x 有什么区别？)
       - `[视频处理]` (为什么我的视频需要这么久？)
       - `[API 指南]` (如何通过 API 调用？)



#### H. 404 未找到 (404 Not Found)



- **为何需要：** 当用户访问一个不存在的 URL 时，提供一个友好的引导，而不是浏览器默认的丑陋错误。
- **设计与流程：**
  1. **页面：`[ (捕获所有未匹配路由) ]`**
  2. **布局：** 全屏居中。
  3. **设计 (保持品牌调性)：**
     - **主题：** “迷失深海”
     - **插画：** 一个可爱的潜水艇或声纳扫描图，显示“无信号”。
     - **大标题：** `404 - 迷失航线`
     - **副标题：** `您所寻找的页面似乎已经潜入深海，无法找到。`
     - **按钮：** `[ < 返回主甲板 (仪表盘) ]` (主色调按钮)
